## 2024-05-14 - [Optimize catalog read queries by preventing unnecessary eager loading]
**Learning:** When using SQLAlchemy's async operations, models with relationships configured to eagerly load (e.g., `lazy='selectin'`) will always fetch that relationship data from the database. In generic service methods (like `get_product`, `get_products`, `get_categories`), if the specific output schema (e.g., `ProductOut`) doesn't require this data, it leads to memory bloat and N+1 query patterns (over-fetching).
**Action:** When a read operation in the service layer doesn't need eager-loaded relationships for its specific downstream use case (such as serialization via basic Pydantic schemas), explicitly chain `.options(raiseload('*'))` to the select statement. This prevents both implicit eager queries and accidental lazy queries in async contexts.
