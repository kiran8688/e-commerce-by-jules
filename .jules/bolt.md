## 2024-05-26 - Prevent wasted eager loads in async SQLAlchemy
**Learning:** In async SQLAlchemy (`AsyncSession`), synchronous lazy-loading is not possible. To workaround this, models might default to eager loading strategies (like `lazy="selectin"`) for relationships to ensure data is available. However, when returning Pydantic response schemas (like `ProductOut`) that omit relationship fields, these eager loads result in wasted N+1 secondary queries.
**Action:** When a router endpoint's response schema does not require relationship data, explicitly pass `.options(raiseload('*'))` to the generic service-layer functions (via a parameter like `load_options`). This protects against silent data omission by throwing an exception if downstream code inadvertently accesses the relationship, and prevents unnecessary database queries from being executed.
