## 2026-07-05 - N+1 Issue Avoidance via `noload('*')`
**Learning:** When returning Pydantic response schemas (like `ProductOut` in `app/schemas/catalog.py`) that omit relationship fields, relationship fields configured with `lazy='selectin'` on the SQLAlchemy models (such as `Product.category`, `Product.images`, `Product.inventory`, `Product.reviews`) will still be eager-loaded by SQLAlchemy, causing wasted database queries and memory overhead (an N+1 equivalent when fetching lists of objects where the data isn't needed).
**Action:** When creating queries in services (e.g. `catalog_service.py` `get_products`) where the related data is not serialized into the Pydantic output, use `.options(noload('*'))` to explicitly prevent eager loading of those relationships, significantly saving DB I/O and CPU overhead. Note: `raiseload('*')` doesn't block explicitly mapped `lazy='selectin'`, but `noload('*')` does.
