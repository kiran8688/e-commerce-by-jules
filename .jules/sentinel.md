## 2024-05-13 - [Fix Timing Attack & Integrity Error in Registration]
**Vulnerability:** The `/register` endpoint used `authenticate_user(db, email, password)` to check if a user already existed. This exposed a timing attack because password hashing (Argon2) is computationally expensive, allowing an attacker to deduce if an email exists by measuring response times. It also created a bug where attempting to register with an existing email but an incorrect password would pass the check but fail with a DB integrity error on insert.
**Learning:** Checking for user existence using an authentication function that hashes passwords inherently leaks existence via timing attacks and fails to handle existing users safely if they provide the wrong password during a registration attempt.
**Prevention:** Always use a dedicated DB query (e.g., `get_user_by_email`) that only checks the email without performing cryptographic operations when verifying user existence during registration or password resets.
