## 2025-02-23 - [Fix Password Oracle Vulnerability]
**Vulnerability:** Registration endpoint was using `authenticate_user` to check for existing users. This created a password oracle vulnerability because `authenticate_user` uses a slow cryptographic hash operation (Argon2) when verifying the password. An attacker could measure the response time to determine if an email address exists in the system (the response would be slower if the user exists because the hash operation is performed, but faster if the user doesn't exist and it returns early).
**Learning:** Checking for user existence using a function designed for login authentication exposes the system to timing attacks. It inadvertently leaks information about which email addresses are registered.
**Prevention:** Always use a simple database lookup (like `get_user_by_email` without any password verification) when merely checking if an email is already registered. Reserve `authenticate_user` strictly for login flows.
