## 2024-05-12 - Timing Oracle and Logic Bug in User Registration
**Vulnerability:** The `/register` endpoint was using `authenticate_user(email, password)` to check if a user already exists. This created a logic bug where registration would attempt to create a duplicate user (and fail with a DB IntegrityError) if the user provided the wrong password for an existing account. More importantly, it exposed a timing oracle vulnerability, as `authenticate_user` performs a slow cryptographic hash if the user exists, but returns immediately if they don't, allowing an attacker to enumerate registered emails via timing analysis.
**Learning:** Repurposing a function that performs cryptographic operations for a simple existence check is dangerous. It introduces timing leaks and unintended side effects. Always separate existence checks from authentication checks.
**Prevention:** Always use a dedicated function like `get_user_by_email` that only performs a simple database lookup to verify user existence. Keep authentication functions strictly for validating login credentials.
