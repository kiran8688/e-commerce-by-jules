## 2026-05-17 - [Password Oracle / Timing Attack in User Registration]
**Vulnerability:** The registration endpoint (`/register`) previously checked for existing users by calling `authenticate_user`. This meant it performed cryptographic password hashing during registration attempts. This causes timing differences depending on whether the user exists or not, exposing a timing attack (password oracle) that allows attackers to enumerate registered users on the platform. It also meant a duplicate registration using a different password for an existing email wouldn't be caught properly (as `authenticate_user` would return `None` because the password didn't match, causing it to proceed and try to insert a duplicate email, resulting in a database integrity error instead of a clean 409).
**Learning:** Using an authentication function to check for existence introduces timing attacks and unexpected behavior since it requires password matching.
**Prevention:** Always use a simple database lookup (like `get_user_by_email`) without cryptographic operations when securely verifying user existence or checking for duplicates.
